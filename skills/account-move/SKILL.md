# 换账号搬家（account-move）

> 克代同堂 Clawdex 的一部分。原创 Miaomiao（GitHub: Miaomiaomeowmeow）。

桌面应用左边的对话列表**按账号分开存**，换号后旧对话不显示；但对话内容存在本机的 Claude 配置目录（`CLAUDE_CONFIG_DIR`，没设就是用户文件夹下的 `.claude`）里的 `projects\`，哪个号都读得到。规矩、技能、记忆也都是本机文件，换号不丢。这个技能把「旧号在做的对话」整理成精简记录，在新号接着做。

下面的 `<配置目录>` 都指 Claude 配置目录；脚本在 `<配置目录>\skills\account-move\move.py`。

## 用户说“搬家”时，照这个做

1. **只搬用户勾的**（全搬太费额度）：换号后克代同堂浮窗会弹一张照旧号左侧栏排好的勾选清单，默认只勾「做到一半被掐断的」和「之前搬过、又有新进展的」；用户点「接过来 N 个」，选择存进 `<配置目录>\clawdex\move-selection.json`，并在新号开一个写着「搬家：只接 move-selection.json 里选的 N 个」的对话
   - 有这份清单：`python -I "<配置目录>\skills\account-move\move.py" plan` → 打印 JSON 搬家计划（已排好「先上级、后分支」，每项写好 kind / parent / children / cutoff / digest 路径 / reason；skipped 里是跳过的和原因）。精简记录已经生成好，不用再 digest
   - 没有清单（用户在别处直接说「搬家」）：先跑 `list`（最近 7 天），把列表给用户看，问接哪几个，别全搬。列表是脚本读的，不花额度
   - `from` / `to` 写账号编号或组织编号都认（`claude-code-sessions\<账号>\<组织>\`）
2. **已归档的、搬过以后没再动过的不搬**（脚本自动跳过）
3. **每个对话**照计划里的 `kind` 做：`progress` = 给 `target` 那个原对话发进度（只含上次搬完以后的新改动）；`new` = 开新对话。**`parent` 不是 null 的先不开**，见下面「分支」：
   - 跳过你自己这个对话（就是用户说“搬家”的那个，在旧号里没有对应）
   - **先读记录还是等用户来再读**：读记录要花新号的额度，所以只有**明显被掐断的**才马上读、接着做；别的等用户进到那个对话说话时再读。判断不靠 AI，只看精简记录里有没有「⚠ 换号时 Claude 正做到一半」（= 最后一个动作是工具调用、之后没再说话）
   - 精简记录路径：有计划就用每项的 `digest`；没有计划时 `python -I move.py digest <编号>`（只要新改动加 `--since <毫秒>`）。最前面是脚本自动整理的**交接摘要**（最后一份任务清单、最后一次小结和当时在问的问题、换号时是不是正做到一半、最近改过的文件、用户最后说的话），后面是只留说的话的聊天记录
   - **「给原对话 xxx 发进度」的**：不开新的，用 `SendMessage`（`to` = 那个 `local_…` 编号）发。做到一半的发：「你在另一个号上又接着做了，那边的精简记录在 `<digest 路径>`，那边是做到一半被掐断的。读一下最后几段，检查掐断的那一步做完没有，然后在这个对话里接着做，别重问已经定的事。」别的发：「你在另一个号上又接着做了，那边的精简记录在 `<digest 路径>`。现在先别读，只回一句「另一个号那边的进度到了，你说一句我就接上」；用户下次说话时，先读记录最后几段再回答。」发完 `python -I move.py done <旧编号> <原对话编号>`
   - **「开一个新对话」的**：用 `start_session`：`initiation: "user_asked"`、`context: "fresh"`、`cwd` = 旧对话的文件夹、`use_worktree: false`、`title` = 旧标题、`effort` = 旧对话的思考程度（不高于自己的）。`prompt` 和 `background` 照下面的模板
   - 开好后 `python -I move.py done <旧编号> <新对话的 local_ 编号> [<旧2> <新2> …]` 记成一对：以后这两个对话来回搬，只互相发进度，不再开新的
   - **分支**（旧号里挂在某个对话下面的）：左侧栏的上下级是「谁用 start_session 开的谁」，没有事后挂上去的办法；新对话在没人开口的第一轮里自己开分支，会被自动审核拦下，别绕。所以：
     - 搬家对话只开 `parent` 为 null 的；给有 `children` 的上级对话的 prompt 末尾加一段：「这个对话在旧号里有这几个分支：<每个分支的标题、文件夹、digest 路径、effort>。用户说「开分支」时，用 start_session 照新对话模板一个个开，开好一个跑一次 `move.py done <旧编号> <新编号>`；被拦的跳过，最后列出来」
     - 汇报表里写清「XX 下面有 N 个分支：进去说一句『开分支』」
4. **左侧栏照搬**（旧号左侧栏什么样，新号就摆成什么样）：
   - 查旧对话在左侧栏的样子：`node "<克代同堂插件目录>\scripts\codex-sort.mjs" describe --claude-session <旧对话的 cliSessionId>` → `title`、`section`（自建分组，null = 没有）、`groupBy`
   - 自建分组：`mcp__ccd_sidebar__list_groups` 看新号有没有同名分组，没有就 `create_group`，再 `move_sessions` 把新对话放进去。按文件夹排的不用动
5. **汇报**：一张表——旧标题、文件夹、新对话链接 `[标题](#local_<id>)`、「已接着做 / 等你来」。再说一句：旧号里那些对话还在，换回旧号还能看到

## 新对话的 prompt 模板

**等你来的**（大多数）：
> 这是用户换账号以后，从旧账号搬过来的对话《<旧标题>》。旧对话的精简记录在 `<digest 路径>`。**现在先别读**（读要花额度），只回一句：「从旧号搬来的，记录准备好了，你说一句我就接着做。」用户下次说话时，先照下面「做到一半的」那段读记录、对一下做到哪，再回答用户说的事。

**做到一半的**（精简记录里有「⚠ 换号时 Claude 正做到一半」）：
> 这是用户换账号以后，从旧账号搬过来的对话《<旧标题>》。旧对话的精简记录在 `<digest 路径>`（原始完整记录的路径写在它第一段）。先读最前面的「交接摘要」，再看聊天记录最后几段：还有什么没做完、已经定下来的东西（别改）。读完用三五句话跟用户对一下：「上次做到 XX，还差 XX，我打算接着做 XX」。先检查掐断的那一步做完没有、结果对不对，再接着把那一步做完（只做到那一步，不开新活）。别重新问已经定过的事。

background 写：用户额度用完换了账号，规矩、技能、记忆都是本机文件照常生效；这个对话的任务就是无缝接上旧对话，用户不想再交代一遍。

## 搬回来（换回原来的号）

照上面一样做：清单只列「上次搬完以后又有动静的」，搬过的对话计划里是 `progress`，只把新改动发给原来那个对话。**搬回来不开新的**：每个对话第一次去另一个号时开一个，脚本记成一对；之后来回搬只给对方那一个发进度。

## Codex 换号

- Codex 的对话存在 Codex 的家（`CODEX_HOME`，没设就是用户文件夹下的 `.codex`）里的 `sessions\`，对话表 `state_5.sqlite` 的 `threads` 每行记着 `creator_account_id`（哪个号建的）
- 换号后旧对话还在 Codex 左边列表里 → 什么都不用做
- 不在了 → 在 Codex 新号里开一个对话说「搬家」：跑 `python -I move.py codex-list`（列出别的号最近在做的对话），用户说接哪个，就 `codex-digest <编号>` 整理成带交接摘要的记录，在当前对话里读完接着做（Codex 不能自己开新对话，一次接一个）

## 终端版 Claude Code 换号（可选：claude-swap）

- 工具：[claude-swap](https://github.com/realiti4/claude-swap)（MIT，`uv tool install claude-swap`）。加号：用另一个号 `claude auth login` → `cswap add`；换号：`cswap switch`
- 对话记录本来就都在配置目录的 `projects\`，换号后 `claude --resume` 就能接着原来的对话，不用搬
- **它换不了桌面应用的号**，桌面应用换号还是走上面的「搬家」
- `cswap list` 会显示当前号的额度用了多少、什么时候恢复

## 只接一个旧对话

用户说“接着 XX 那个对话做”：`list 30` 找到编号 → `digest` → 在当前对话里读那份记录接着做（不用开新对话）。

## 注意

- 桌面应用的对话列表在 `%LOCALAPPDATA%\Claude-Data\claude_*\claude-code-sessions\<账号编号>\<组织编号>\local_*.json`。桌面应用改版后路径可能变，脚本报“没找到”就先去找新位置
- 只读旧号的列表，**不改、不复制**桌面应用自己的文件
- 搬家记录在 `<配置目录>\account-move-records\`（精简记录按日期放，`搬家记录.json` 记搬过哪些）

## 踩过的坑

- **同名对话会互相盖掉记录**：digest 完马上把文件改名，后面加旧编号前 8 位
- **很大的记录（几百 MB）在 PowerShell 里 digest 可能失败**、没有输出；改用 Bash 跑同一条命令
- **新开的对话在左侧栏全挂在「搬家」对话下面**，归档搬家对话会把它们一起归档：开完用 `detach_session` 拆成独立的，再建分组、`move_sessions`。由用户说「开分支」开出来的分支**不要拆**
- 少数 `start_session` 会被自动审核拦下（不给原因，重试也拦）：别硬试，汇报时列出来，请用户自己在新号开对话、贴那份精简记录路径
